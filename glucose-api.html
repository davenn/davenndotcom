API reference

Glucose API

Read continuous glucose monitor data over HTTP. Plain text for microcontrollers, JSON for everything else.

Connect

One base URL, one token, no session or handshake. Pass the token as ?token= or as an X-BG-Token header.

curl "https://davenn.com/api.php?action=bg_embed&token=$TOKEN"

270,3,5,0

All reads are GET. A missing or wrong token returns 401; an unknown action returns 404.

Endpoints

ActionReturnsParameters
bg_embed Plain text, one line. ~10 bytes spark 1–60, low, high
bg_latest JSON, newest reading —
bg_history JSON, every reading plus a summary hours 1–168, low, high
bg_daily JSON, one row per local day days 1–365, low, high
bg_refresh Forces a live pull. POST 45-second cooldown

low and high set the in-range band, defaulting to 70 and 180. Readings are stored every 5 minutes, so hours=24 is about 288 of them — roughly 18 KB of JSON.

Formats

bg_embed — plain text

Four integers, then an optional sparkline row of mg/dL values, oldest first.

bg_latest — JSON

{"reading":{"at":"2026-09-18T13:46:47+00:00","mgdl":270,
            "trend":"FortyFiveUp","minutes_ago":5}}

bg_daily — JSON

coverage_pct is the share of the day's 288 slots that have data. A day below ~70% has sensor gaps, and its percentages should be read with that in mind.

{"day":"2026-09-17","readings":237,"avg_mgdl":136,
 "min_mgdl":72,"max_mgdl":269,"low_count":0,"high_count":44,
 "in_range_pct":81,"coverage_pct":82}

Examples

Shell

curl -s ".../api.php?action=bg_daily&days=7&token=$TOKEN" | jq '.daily[].in_range_pct'

JavaScript

const r = await fetch(`${BASE}?action=bg_latest&token=${TOKEN}`).then(r => r.json());
if (r.reading && r.reading.minutes_ago <= 15) render(r.reading.mgdl);

ESP32 / C

No JSON parser, no allocation — a fixed stack buffer and one sscanf.

int mgdl, trend, mins, inRange;
if (sscanf(buf, "%d,%d,%d,%d", &mgdl, &trend, &mins, &inRange) != 4) return;
if (mgdl <= 0) return;              // nothing stored yet
drawArrow(ARROWS[trend]);
drawNumber(mgdl, mins > 15 ? DIM : BRIGHT);

Worth knowing

  • Never show an old number as current. Check minutes_ago — dim past 15 minutes, hide the number past 60. A stalled poller and a dead sensor look identical from the client.
  • Pin the root CA, not the leaf. The site certificate rotates on renewal; embedding it means a device dies twice a year. Embed Go Daddy Root Certificate Authority — G2.
  • Reads never touch the CGM vendor. Everything is served from stored readings, so extra clients cost the upstream API nothing.
  • Poll no faster than 60 seconds. New readings only arrive every 5 minutes.
